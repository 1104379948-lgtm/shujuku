# World 后台数据库使用说明

World 后台不是一个“多几张表”的模板。它的作用是：让故事世界在主线正文之外继续运转。

普通数据库表只记录主角、角色、背包、任务、纪要这些“眼前发生的事”。World 后台记录的是更远一层的东西：外面的势力在做什么，消息有没有传出去，主角的行为有没有留下痕迹，敌人有没有开始行动，某个地区有没有正在发酵的事件，哪些秘密还没有公开。

你正常聊天，它在正文结束后自动跑一轮。你不需要每轮手动操作。

## 它能带来什么效果

安装后，故事会多一层后台状态：

- 主角在某地闹出动静，可能先变成“风声”，之后才影响声誉。
- 私密行为不会立刻全世界都知道，会先进“黑盒”，除非有目击者、证据或传播链。
- 势力、敌人、地区事件可以在主角没直接看见的时候推进。
- 世界状态会被整理成一段摘要，注入给后续 AI，让正文能接住之前的后台变化。
- 每轮推演前会保存 checkpoint，推坏了可以回滚。

简单说，它让世界不是只围着主角刚刚说的那句话转。

## 一轮推演到底怎么跑

每次 AI 正文回复结束后，`World 推演器` 自动执行一次。

它会读取这些信息：

- 当前默认数据库表：时间、地点、主角、重要角色、背包、任务、纪要、选项。
- World 后台表：事件链、势力、风声、声誉、经济、敌人、影响链、黑盒、地区事件、自定义状态。
- 最近几轮正文。
- 当前世界书渲染出来的内容。
- 当前启用的 World 模块规则。

然后它会让 AI 只判断“这一轮发生了哪些后台变化”。

它不会要求 AI 重写整个世界状态，也不会让 AI 把所有表重新输出一遍。只输出本轮变化。

推演成功后，它会写入这些后台表：

- `World事件链表`：正在推进的冲突、行动、阴谋、调查、危机。
- `World势力表`：组织、家族、帮派、机构等的目标、状态和最近动作。
- `World风声表`：流言、公告、传闻、舆情、传播中的消息。
- `World声誉表`：主角在市井、势力、秩序层面的评价变化。
- `World经济表`：某个地区或市场的气候、信号和影响。
- `World仇敌录表`：敌人、仇恨原因、严重度、报复阶段、当前计划。
- `World影响链表`：一个变化如何影响另一个变化。
- `World信息黑盒表`：暂时不该公开给世界的秘密、痕迹和暴露风险。
- `World区域突发事件表`：地区性事件、剩余轮数、冷却。
- `World自定义模块状态表`：你自己扩展的额外世界状态。

最后，`World 摘要器` 会把这些后台状态压成一段给正文用的摘要，写入 `World世界摘要表`，并刷新世界书注入。

## 提示词是怎么要求 AI 的

默认推演提示词的核心意思是：

```text
你是 World 后台推演器，只输出严格 JSON。

根据默认前台事实、World 后台状态、最近正文和世界书内容，输出本轮发生变化的 World 状态。

规则：
只输出启用模块；
只输出本轮发生变化的记录；
私密行为如果没有目击者或痕迹，必须进入 blackbox，不能直接改变 winds、reputation 或公开势力态度。

只输出 JSON 对象，不要输出解释、Markdown 或自由文本；
只输出启用模块；
只输出本轮发生变化的记录。
```

也就是说，它不是让 AI 续写剧情，而是让 AI 做“后台结算”。

比如正文里写了：主角夜里偷偷潜入商会仓库，没被人发现，但弄坏了门锁。

World 后台更合理的处理是：

- 不立刻让全城都知道主角潜入过。
- 可以在 `World信息黑盒表` 记录“仓库门锁损坏、可能留下痕迹”。
- 可以在 `World势力表` 更新商会后续警觉。
- 如果后来有人发现门锁，才可能生成 `World风声表` 或影响声誉。

这就是“黑盒”和“传播链”的意义。

## 用户实际会看到什么

你不会在正文里直接看到一堆后台表。

默认只有 `World世界摘要表` 会注入世界书。它会把后台变化整理成类似这样的内容：

```text
<world_state>
城南商会开始加强夜间巡查。坊间暂未出现明确传闻，但仓库门锁损坏留下了可追查的痕迹。黑市方面对近期巡查变化有所察觉。
</world_state>
```

后续正文 AI 读到这段摘要，就能自然接上世界变化，而不是每轮都忘记外部环境。

后台明细表默认不直接注入正文，因为里面可能有玩家可见但角色未知的信息，例如秘密、敌人计划、未公开证据。

## 怎么安装

你只需要导入两个 JSON 文件。

### 第一步：导入数据库模板

打开 shujuku 面板，进入“表格”页。

找到“当前聊天正在使用”。

点击“导入到当前聊天”。

选择：

```text
world-engine-database-native-design/dist/world-database-template.json
```

注意：要导入到“当前聊天”，不要只导入到“全局模板预设”。全局导入只是保存预设，不一定会立刻用在当前聊天上。

### 第二步：导入脚本包

打开“脚本管理”。

点击“导入脚本包”。

选择：

```text
world-engine-database-native-design/dist/world-script-package.json
```

看到导入预览后，点击“确认导入”。

导入后，保持这些脚本启用：

- `World 初始化器`
- `World 推演器`

其他脚本可以先保持默认状态，不用手动管。

### 第三步：重新进入聊天

导入完成后，重新打开当前聊天，或切换到别的聊天再切回来。

这样 `World 初始化器` 会自动准备后台基础数据。

## 怎么确认装好了

打开数据库表格，能看到这些表就说明模板导入对了：

- `World元数据表`
- `World事件链表`
- `World势力表`
- `World风声表`
- `World信息黑盒表`
- `World推演台账表`
- `World世界摘要表`
- `World存档点表`

然后正常发一条消息，让 AI 回复正文。

回复结束后，查看 `World推演台账表`：

- `success`：推演成功。
- `failed`：推演失败，看 `error` 和 `raw_response`。
- `skipped`：本轮跳过，可能是重复消息、未启用、或设置了隔几轮推演。

再看 `World世界摘要表`，如果出现新的摘要，说明世界状态已经准备给后续正文使用。

## 平时怎么用

正常聊天即可。

你不需要每轮打开表格，也不需要手动运行脚本。

推荐使用方式：

1. 正常写剧情和行动。
2. 让 AI 回复正文。
3. World 后台自动结算外部影响。
4. 如果感觉世界没有接住变化，再去看 `World推演台账表` 和 `World世界摘要表`。

如果你想暂停后台推演，把 `World元数据表.enabled` 改成 `否`。

如果你想恢复，把它改回 `是`。

## 什么情况下它特别有用

适合这些故事：

- 城市、江湖、学院、宫廷、公司、黑帮、宗门等有多方势力的故事。
- 主角行为会带来外部后果的故事。
- 需要秘密、调查、流言、敌人计划慢慢发酵的故事。
- 不希望“主角没看见的世界就完全静止”的故事。

不太适合这些情况：

- 只想单纯一问一答，不需要长期世界状态。
- 不想让 AI 额外做后台结算。
- 当前模型很难稳定输出 JSON。

## 常用开关

在 `World元数据表` 里可以改这些字段：

| 字段 | 怎么填 | 效果 |
| --- | --- | --- |
| `enabled` | `是` 或 `否` | 开关 World 推演。 |
| `evolve_every` | `1`、`2`、`3` 等 | 每几轮推演一次。`1` 是每轮都推演。 |
| `active_preset` | `default` | 使用哪个推演提示词。普通用户保持 `default`。 |
| `mode` | `classic`、`free`、`mixed` | 普通用户保持 `classic`。 |
| `api_preset_override` | 留空或 API 预设名 | 留空就用当前主 API/剧情推进 API。 |

## 出问题怎么看

### 没有推演

检查：

- 有没有导入数据库模板到“当前聊天”。
- 有没有导入脚本包。
- `World 初始化器` 和 `World 推演器` 有没有启用。
- `World元数据表.enabled` 是否是 `是`。
- 当前是否使用 SQLite 模式。

### 推演失败

打开 `World推演台账表`。

看最新一行：

- `error`：失败原因。
- `raw_response`：AI 原始返回。
- `parsed_json`：成功解析后的结果。

最常见失败原因是 AI 没有输出严格 JSON，而是输出了解释、Markdown 或多余文本。

### 世界书没体现变化

检查：

- `World世界摘要表` 有没有新摘要。
- `World 摘要器` 有没有成功运行。
- 世界书注入目标是否选对。
- 后续正文是否真的读取了注入世界书。

### 感觉后台知道了不该知道的事

检查 `World信息黑盒表` 和 `World风声表`。

合理情况是：

- 私密、无人发现的事进入 `World信息黑盒表`。
- 已传播、有人知道、公开可见的事进入 `World风声表` 或影响声誉。

如果模型把秘密直接写成公开风声，说明这轮 AI 推演质量不好，可以用 checkpoint 恢复到上一轮。

## 怎么恢复

每次推演前都会写一个 checkpoint。

恢复方法：

1. 打开 `World存档点表`。
2. 复制要恢复的 `checkpoint_id`。
3. 在脚本管理里手动运行 `World 恢复器`。
4. 输入这个 `checkpoint_id`。

恢复器会先写一个紧急备份，再恢复你选的存档点。

## 不建议普通用户手改的表

这些表可以看，但不建议手改：

- `World事件链表`
- `World势力表`
- `World风声表`
- `World声誉表`
- `World经济表`
- `World仇敌录表`
- `World影响链表`
- `World信息黑盒表`
- `World区域突发事件表`
- `World自定义模块状态表`
- `World推演台账表`
- `World存档点表`

如果只是想控制开关，改 `World元数据表` 就够了。

## 给会用控制台的人

普通用户不需要这一段。

```js
await window.AutoCardUpdaterAPI.importTemplateFromData(templateData, {
  scope: 'chat',
  presetName: 'World数据库模板',
});

window.AutoCardUpdaterAPI.importUserScripts(scriptPackage);
```

`templateData` 是 `dist/world-database-template.json` 的 JSON 内容。

`scriptPackage` 是 `dist/world-script-package.json` 的 JSON 内容。

## 给维护者

这些不是安装命令，是重新生成 dist 文件用的命令：

```bash
node world-engine-database-native-design/export-assets.mjs
node world-engine-database-native-design/verify-assets.mjs
```

维护源文件：

- `world-template.js`：数据库模板来源。
- `world-scripts.js`：脚本包来源。
- `export-assets.mjs`：重新生成 dist 文件。
- `verify-assets.mjs`：检查 dist 文件和维护源是否一致。

检查一致性只能说明 dist 是从当前维护源生成的，不能说明真实运行一定成功。
